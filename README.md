# 本地 AI 圆桌会议

一个能跑的最小圆桌引擎，加一个本地的网页界面。**还不花钱、还不联网**，因为我想让你先把"圆桌的脾气"摸清楚，再去接真模型。

假模型的台词是写死的演示文本，所以所有统计**只反映引擎的行为，不反映真模型的行为** —— 它现在的作用是：让你在没有账单的情况下，把"自由轮"和"回合制"的区别、冷场、收敛、预算闸，全都亲眼看一遍。

---

## 这个仓库里没有你的东西

clone 下来是**干净的**：没有 API key，没有聊天记录。

| 目录 | 里面是什么 | 在仓库里吗 |
|---|---|---|
| `data/members.json` | 成员表，**含 API Key** | ❌ 不在 |
| `sessions/` | 你的每场对话 | ❌ 不在 |
| `out/` `logs/` | 每次调用的完整 prompt 和回复 | ❌ 不在 |

第一次跑会自动从 `src/seats.js` 播种一份**假成员**（不花钱的那种）；要接真模型，自己在成员里填 key。

key 只在两个地方出现：`data/members.json`，和你本机发出去的 HTTP 请求头。页面永远只拿得到后四位，日志里不记 key。

一条命令确认干净：

```bash
git grep -E "sk-[A-Za-z0-9_-]{10,}" $(git rev-list --all)
```

没输出就是干净的。**别用 `git add -f` 绕过忽略**——那是唯一能让它漏出去的操作。

## 先开网页

**双击 `start.bat`。** 它会检查 node、检查端口（已经在跑就直接开浏览器）、起服务、再帮你把页面打开。那个黑窗口别关，关了服务就停。

或者手动：

```bash
node server.js
```

然后浏览器打开 **http://127.0.0.1:4173**

- 左边是本地记录（`sessions/*.json`），点一下载入；**鼠标移上去右边会出现 `×`，点掉就移进回收站**
- 左下角 **「回收站」**：删掉的会话都在那儿，能恢复，也能彻底删（`sessions/.trash/`）
- 顶上选预设和种子；**`轮` = 最多走几轮，`每轮` = 这一轮最多几个人发言**
- **「资料」** 给这一场喂背景材料，开会前每个人都会读到
- 座位芯片点一下可以让人闭嘴
- 底下写一个议题 → **发言并开跑**，消息会一条条流出来
- 开着的时候 **「停止」** 能立刻掐断 —— 已经说出去的都留下来了，正在生成的那一句作废
- **把 .json / .jsonl / .md 拖进窗口**，就能载入那段对话接着聊
- 「导出」把当前会话存成 json

聊天记录是 `sessions/` 里的普通 json 文件。你可以用编辑器打开、改、备份、发给别人 —— 这就是"存在本地"的意思：你看得见它。

## 成员：谁能上桌，他们是什么人

点右上角的 **「成员」**，右边滑出来一张表。

每个成员是一行，点彩色小圆点就是"这一位参加 / 不参加"，点「编辑」进去改：

| 字段 | 干什么用的 |
|---|---|
| 名字 | 页面上显示的名字 |
| 角色设定 | 他相信什么、关注什么、站在哪一边 |
| 规则 | 一行一条，**写禁令比写鼓励有用** |
| 附和倾向 | 越高越容易说「我同意」。挑刺者应该在 0 附近 |
| 沉默概率 | 0 = 必说；0.6 = 基本不主动开口（就是"沉默权"那根轨） |
| 渠道 | 提供方 + 模型名 + 接口地址 + API Key |

一个成员 = **一个人格 + 一条渠道**。所以"一个 key 一个成员"是成立的，而且应该这样做：五个人接五家不同的模型，它们吵起来才有意义；五个人接同一个模型，你只是花五倍的钱听同一个脑子说五遍。

**成员存在 `data/members.json`**，是普通 json，可以直接用编辑器改，刷新页面就生效。这个文件里会有 API Key，已经写进 `.gitignore` 了。

关于 key，有三件事是刻意设计的：

- **页面永远拿不到明文 key。** 接口只回"有没有 key"和后四位（`····1234`）。
- **不改就不动。** 你只改人设时，请求里根本不带 `apiKey` 字段，服务端保留原来那把。
- **清掉要明确说。** 传空字符串才会删除。

**预设和成员表的关系**：预设是这一趟的**临时覆盖**（"正式会议"会强制所有人不许沉默），改完不写回文件；成员表是**长期设置**。所以你在成员里把人调成"懒得说话"，开"正式会议"时他照样必须开口 —— 这是那根轨的设计，不是 bug。

## 接真模型

成员里把渠道从「假模型」换成别的、填模型名和 key，就是真调用了。

| 提供方 | 接口 | 模型名 |
|---|---|---|
| DeepSeek | OpenAI 兼容 | 点「拉列表」直接从服务商取 |
| 智谱 GLM | OpenAI 兼容 | 同上 |
| 豆包（火山方舟） | OpenAI 兼容 | 填**推理接入点 ID**（`ep-...`），不是模型名 |
| OpenAI / 各种中转 | OpenAI 兼容 | 同上 |
| Anthropic | messages 接口（单独一支） | 同上 |

**模型名不用手打了。** 成员编辑里点「拉列表」，程序去服务商的 `/models` 要一份你现在这个 key 能用的清单，选一个就填进去。换了服务商、key 又已经存着的话，它会自己拉一次。

拉不到就退回手打——那条路一直留着，不会因为一个接口不配合就把你卡死。

三个必须知道的事：

**1. 模型名写错，密钥是对的也没用。** 服务商会回 400 和一句原文，比如 `模型不存在，请检查模型代码`。所以列表之外还有 **「测一下连接」**：只发一句话，把服务商的**原文**贴回来，不用开一整场会议去试。

**2. 现在的 flash 系列多半是"思考模型"。** 它会先花几百个 token 在思维链上，`MAX_TOKENS` 给少了就会 `finish_reason=length` 而 `content` 是空字符串——看起来像"模型没说话"，其实是预算不够。这里设成了 2000（`src/speaker.js`）。代价是慢和贵，所以**开会用的成员建议挑非思考模型**。

**3. 一家挂了不拖垮整场。** 某个成员报错，页面会显示「某某 连不上：<服务商原文>」，这个人从这一场里摘掉，其他人接着说。全员连不上才散会。

## 资料：让他们先过目，也当绳子

点 **「资料」**，贴进去，按保存。它存在这一场里（`session.brief`），换会话就换一份。

它会进每一次调用的 prompt，不只是开场那一次 —— 只在开场读一遍的话，第三轮就忘了，跑得比谁都快。

prompt 里因此多了三条：

- 资料是这次讨论**唯一的事实来源**，资料里没有的数字和事实不要编
- 想说的东西如果和议题、资料都无关，就**回「过」**（沉默权被借来当刹车）
- 议题、资料、纪要、最近六条 —— 每次只带这些

三条限制，都是故意的：

**1. 只带前 3000 字。** 再长的话，每次调用都要重读一遍，钱和延迟都不划算。超出部分界面上会告诉你"不算"。

**2. 它是软约束，不是硬检测。** 真跑题了，提示词只能劝，不能拦。硬检测要么另花一次模型调用让裁判判，要么写一堆不可靠的关键词规则 —— 后者会让你误以为拦住了。这里不做假的。

**3. 越具体越有用。** "AI 行业趋势"这种资料等于没有；"我们只有 300 元预算、两个成员、其中一个是思考模型"这种，能立刻把跑题的话挤出去。

你想让资料更硬，有两个方向：把资料写成条目（编号、短句），或者把 `src/prompt.js` 里那句"资料是唯一事实来源"再收紧。

## 辩论：先定立场、再定辩位

点 **「辩论」**：

- 辩题就是这一场的**议题**（会话标题）
- 上面两个框填**正反方的预设立场**——他们必须论证到底，不许中立
- 下面给每个成员选**阵营**和**辩位**（一辩 / 二辩 / 三辩）
- 再下面选**谁先开口**：正方先手，还是反方先手
- 勾上**「逐轮确认」**：每轮走完就停，下一轮谁先开口由你点
- 或者选一个**主持 AI**：每轮开头它定先手、写一句"这一轮必须回答什么"，你只管看

保存之后会自动把预设切到「辩论」。

### 主持 AI

选一个成员当主持人，它每轮开头做三件事：**承接、发现、启下**。

它不是报时员，是主编。机械地"挑一个没被回答的说法"没有意义——那种东西辩手自己会补。它要找的是**双方都没点破、但一旦点破整场就会变**的那件事。

真实输出长这样（`嘎啦玛` 当主持，正方反方是假模型）：

```
承接：第1轮开场，双方尚未交火。
有意思的是：双方大概率默认孤独与连接互斥，但高连接恰恰可能是新型孤独的温床。
本轮问双方：连接密度越高，孤独是被消解还是换了形态？请各自表态
```

第一轮就会开始找**没被验证的前提**——这是"发现"该干的事，不是"你们再说说"。

它输出的四样东西，各有各的去处：

| 字段 | 长什么样 | 去哪儿 |
|---|---|---|
| `recap` 承接 | `承接：…` | 只显示，让后续轮次有上下文 |
| `angle` 发现 | `有意思的是：…` | 进 prompt（`【主持人的观察】`） |
| `focus` 启下 | `本轮问正方：…` | 进 prompt（`【主持人这一轮的问题】`） |
| `first` 先手 | 一个小标签 `反方先` | **只改顺序，绝不写进正文** |

顺序和内容分两条路是故意的。早先我把「这一轮反方先，请正方回答……」整句发给所有人——正方看到「反方先」以为自己这轮不用说话，反方看到「请正方回答」以为该让出去，两边一起读歪。

问谁是分开标的：`to` 指到正方，正方收到的 prompt 写「这个问题是问你的：必须正面回答」，反方收到的写「这个问题是问对方的：你可以借它进攻」。

**禁止它做的事**：评谁占上风、给结论、总结双方观点、说「请深入讨论」。位置一多，主持就会开始替辩手说话。

**主持最好别用场上的辩手本人。** 换个成员，哪怕同一个 key。

代价：**每轮多一次调用**。

有了主持 AI，「逐轮确认」可以关掉——它会把一轮接一轮推下去。想按暂停的时候按「停止」就行。

**发言顺序是固定的**：正方一辩 → 反方一辩 → 正方二辩 → 反方二辩 → …，一轮里每个人说一次。这个顺序不是随机的，辩论的规矩本身就是它的一半。

**辩位决定任务**，这不是称呼问题：

| 辩位 | 该干什么 |
|---|---|
| 一辩 | 立论：先给定义和判断标准，再给两三条理由 |
| 二辩 | 质询：抓对方一辩的一个具体说法，指出它错在哪，逼它回答 |
| 三辩 | 总结：收束本方，指出对方到现在还没回答的那个问题 |

另外两条硬规则：**不许认同对方**，**不许回「过」**。有人站着不说话，辩就进行不下去。

两个容易踩的地方：

1. **辩论不看成员启用开关。** 你把人排到反方二辩，他就站在那儿——开关是给其他预设用的。
2. **一轮 = 每人一次。** 想辩三个回合就把顶上的「轮」改成 3，那就是 3 轮 × 人数 次调用。

另外一条在这一节之外的规矩，但辩论里最有用：

**你插话 = 主持人下指令。** 你说「进入攻守环节，请反方先进攻」，下一轮每个人拿到的 prompt 里会多一段【主持人刚刚说】，并且**这一轮的辩位任务会被撤掉**——因为两套指令同时在场时，模型会服从先出现的那个（辩位），你的话就等于没说。

**勾「逐轮确认」更彻底。** 每轮走完引擎就停，页面上出现「这一轮结束。下一轮谁先开口？[正方先][反方先]」。点一下，才走下一轮。顺序不再由程序决定，由你。

## 也能在命令行里跑

```bash
node run.js                      # 看「茶话会」
node run.js --preset=吵架         # 换预设：正式会议 / 茶话会 / 吵架 / 静默观察
node run.js --compare            # 同一个议题，四个预设全跑一遍，出对比表
node run.js --topic="你想聊的事" --seed=3
```

不需要 `npm install`，不需要 Docker，不需要联网。只有 `node` 一个要求。

每次跑完会留下两样东西：

- `out/<预设>-seed7.md` —— 给人看的对话记录
- `out/logs/<预设>-<时间>.jsonl` —— 给机器看的完整日志（每次调用的 prompt 和返回原文都在里面）

`--seed` 是随机种子。**同一个种子，结果一模一样**；换种子，看另一种走法。这不是玩票：自由轮天生不可复现，没有种子你连"刚才那步为什么是它说话"都查不了。

## 先看这个对比表

种子 7 跑出来的：

| 模式 | 发言 | 过 | 调用 | 字数 | 末轮新 | 末轮复读 | 末轮附和 | 轮 | 停止原因 |
|---|---|---|---|---|---|---|---|---|---|
| 正式会议 | 15 | 0 | 15 | 466 | 3 | 2 | 0 | 3 | 轮数到 |
| 茶话会 | 17 | 8 | 25 | 537 | 0 | 0 | 4 | 5 | 3 轮滑窗：新 3 / 重复附和 7 |
| 吵架 | 25 | 0 | 25 | 764 | 2 | 3 | 0 | 5 | 预算用尽 |
| 静默观察 | 4 | 6 | 10 | 117 | 1 | 1 | 1 | 2 | 轮数到 / 冷场 |

这张表里有四件事值得盯：

1. **"过"也要花钱。** 静默观察只说了 4 句话，却调用了 10 次 —— 因为"我要不要说话"这个判断本身也是一次模型调用。沉默不是免费的。
2. **吵架模式最贵，而且它不会自己停。** 25 次调用全靠预算闸掐断。如果预算闸当时设成 200，它就会说满 200 次，内容还越来越水（末轮 3 条复读）。
3. **茶话会最后一轮：4 条发言，0 条新论据，0 条复读，4 条纯附和。** 也就是说那一整轮，剥掉"我同意""这句我认""我这边结论一样"之后，一个字都不剩。收敛检测就是在这一轮之后把它按停的（3 轮滑窗：新 3、重复附和 7）。
4. **纯附和是单独一栏的。** 它不算新论据，也不算复读 —— 因为它比复读更彻底：复读至少还试图说点什么，纯附和连试图都没有。

## 四根轨在哪个文件里

你要的"调节器"，实质是这四个东西，它们分居四处，各自独立：

| 轨 | 它在哪 | 现有实现 |
|---|---|---|
| **发言权**：谁定下一位 | `src/schedulers.js` | 固定序列 / 主持点名 / 自荐抢话 |
| **沉默权**：能不能不说 | 假模型看 `src/seats.js` 的 `passRate`；真模型看 `src/prompt.js` 里那句「过」的规则 | 0 = 必说；0.8 = 基本闭嘴 |
| **终止**：什么时候散 | `src/stopper.js` | 轮数 / 收敛（3 轮滑窗）/ 预算 |
| **人格**：轮到它时它是个什么人 | `src/seats.js` 里的 `persona` `rules` `conformity` | 五个固定角色 |

预设（`src/presets.js`）只是把这四根轨摆成四种组合。**没有第五种代码路径** —— 切换模式就是换一个调度器、一个终止器。

顶上那两个数字框是这两根轨的临时旋钮：**`轮`** 覆盖"什么时候散"（压过预设自带的轮数），**`每轮`** 覆盖"谁说话"（每轮只让 N 个人说，说完就进下一轮）。它们只作用于这一趟，不写回成员表，也不改预设。

「停止」走的是另一条路：它掐断页面和服务端之间的连接，服务端跟着把在飞的请求 abort 掉，**已经落进对话的句子全部保留**，正在生成的那一句丢弃。

引擎本身在 `src/engine.js`：一个 `while` 循环，加三个可插拔的策略。你以后加第五种模式，不用碰它。

## 三个今晚就能改的实验

改完直接 `node run.js` 看差别。每个实验都只需改动一两个数字。

**实验一：把自由轮调成"真的自由"**

**实验三：加第六个座位**

## 已知的粗糙处（不用惊讶）

- 假模型台词写死，所以"新论据/复读/附和"的统计只说明检测器在工作，不说明讨论质量。
- 检测器靠"剥掉附和套话 + 两字组新鲜度"，仍然是**筛子不是裁判**。它会漏（换了说法的废话放过去），也会误伤（"我不同意"四个字没带新词，被判成"无新词"）。想调敏感度：改 `src/text.js` 的 `MIN_EFFECTIVE`、`FILLER`、`PUSH`，然后 `node tools/check-detector.js` 看效果。
- 收敛检测用的是 3 轮滑窗，比"连续两轮"稳，但仍然是个代理指标 —— 真退化是渐进的，不存在干净的判据。
- 网页只绑在 `127.0.0.1`，同一局域网的其他设备打不开。这是故意的，等你哪天真要手机看再说。
- 导入只认**我们自己产出的**三种格式。别人家的聊天记录导出（比如微信、ChatGPT 的导出包）认不出来，会直接报错。
- 页面里任何没被接住的错误都会在底部弹一条提示，不再静默失败。要看细节按 F12 打开 Console。改完前端文件**刷新一下浏览器就行**，不用重启服务 —— 静态文件是每次请求现读的。- 抽屉标题右边的 `v3` 是前端版本号。改了前端就改一下 `public/app.js` 顶部的 `BUILD`。**排查"我改了怎么没用"时，先看这个号。**- 每个请求都会往 `out/requests.log` 记一行（方法、路径、状态码、耗时）。"点了没反应"的时候，第一件事是看请求有没有到服务端。
- **成员表里的"沉默概率"只对假模型生效。** 真模型的沉默完全由提示词里那句「没有新东西可说时，只输出一个『过』」决定，所以你在成员里把概率调到 0.9，接真模型的人照样会说话。要真的让他闭嘴，得改那句话。
- **思考模型在长上下文里会"说不出话"。** `glm-5.3-flash` 这类模型会先花大量 token 在思维链上，预算不够时 `finish_reason=length`、正文是空的。现在这种情况算"这一轮没说话"，人不会被摘掉，下一轮还轮得到他；真掉线（网络/鉴权）才会被摘掉。两种都会**记进会话**，刷新之后还看得见。辩论时一方全员掉线，当场结束，不会让另一边对着空气吵。
- API 密钥：目前不存在，因为还没接 API。接的时候会放在 `.env` 之类的本地文件里，不进代码、不进日志、不进页面。
